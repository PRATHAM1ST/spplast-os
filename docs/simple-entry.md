# Simple stock app

Home shows current company-owned scrap, grinding and granules stock. Use one of four actions: **Scrap in**, **Grinding output**, **Granules output**, or **Material sold**. Navigation is just Home, Stock and Entries.

Enter a date and bags (count × kg per bag), or switch to total kg. A material name, photo and colour are optional. Grinding and granules need no input record; expand **Also record material used** when you want to deduct input stock. Scrap can be sold directly from Stock.

Saved entries immediately affect stock and have Edit and Delete controls. Updates apply only the quantity difference. Deleting a sale restores stock; deleting production restores its recorded input. An entry cannot be reduced below material already used or sold. Delete is reversible at the data level: the record and an audit trail are retained, while the entry is hidden and its stock movements are offset. Earlier production records remain visible under Entries and their posted balances are included in stock.

Offline entries and unfinished new-entry drafts are encrypted on the device. Pending changes are reflected in the displayed stock and uploaded on reconnection. The Saving indicator opens retry/conflict tools if a server-side check rejects an entry.

- Enter the device passphrase once per local calendar day. Reloading or reopening the same browser restores the unlock until midnight. Signing out removes it immediately. Online identity checks and the existing offline-session expiry still apply.
- The device remembers a non-exportable Web Crypto key in IndexedDB, never the passphrase. Treat a device remembered for the day as unlocked. Clearing browser data removes the remembered key and local drafts.
- Choose **Add photo & colour**, attach a close-up, and tap a suggestion or the material in the image. Common swatches and custom colours are also available. Suggestions are approximate visual references, not calibrated colour measurements or polymer/grade identification.
- The colour and photos stay linked to the entry. Existing private photo storage handles uploads.

## Deployment

Apply `npm run db:migrate` with `DATABASE_ADMIN_URL` configured before deploying this UI. Migration `006_simple_entries.sql` adds the ledger and extends the existing command/workspace functions without dropping old records. The demo/test SQL bundle is generated by `npm run db:bundle`. No new API keys are needed. Photo uploads still need the existing S3 configuration.

Colour extraction uses [fast-average-color](https://github.com/fast-average-color/fast-average-color), MIT licensed, entirely in the browser. No external AI service or additional environment variables are needed. UI work used the installed Apache-2.0 [frontend-design skill](https://github.com/anthropics/skills/tree/main/skills/frontend-design).
